## 维护约定

- 改动存储层或规则层后，至少跑 `selftest_migrations`、`selftest_storage`、`selftest_care`、`selftest_commands`；涉及协议层时补跑 `selftest_protocol`。
- 每次发版严格按 `RELEASE.md` 走，不在别处另立口径。
- 每次发版后在本文件追加一行，注明日期、版本、变更要点与验收结果。
- 归档的开发计划为只读历史，不再回填；新决策写进本日志或 `DEVELOPMENT.md`。
- 2026-10-09 元数据补全：`metadata.yaml` 已补 `repo`、`tags`、`support_platforms` 三个可选字段，版本号保持 `v0.1.0` 不变，不构成版本变更。`support_platforms` 按主流适配器声明，依据是插件代码不含任何平台适配器特判；尚未逐平台实测，若某平台出现主动消息发不出的情况，收窄该列表即可。
- 2026-10-09 分类与简介定稿：`metadata.yaml` 新增 `category: 生活`（市场 7 个分类为三方集成、生活、工具、长期记忆、知识库、娱乐、其他，值须写中文字面量；曾短暂写成三方集成，同日按主人要求改为生活）。该字段不在官方发布文档的字段表内，但市场实际支持，已有插件如此声明并生效（如 `astrbot_plugin_youshusearch`），属约定俗成用法。同日把 `desc` 换成「读取华为运动健康云数据（步数、睡眠、心率、压力、血氧、训练），并使聊天Bot在对话中自然地关心你的健康。」，GitHub 仓库简介同步为该句加「AstrBot 插件：」前缀；`short_desc` 未动。改完需在 Cloud 发布页对该插件重新提交一次，市场才会重新解析分类与描述。
- v0.1.0 的 Release 附件保持打 tag 时刻的内容，其中的 metadata 不含上述三个新字段；不影响安装与运行，新字段随下一个版本自然带上。
